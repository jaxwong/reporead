# RepoRead Android app

Kotlin/Compose client: GitHub sign-in through the backend, connected repositories, folder/note browsing, the isolated technical-Markdown reader, an offline cache, reading progress with Continue Reading, bookmarks, and highlights with notes, and what changed since the version last read. It talks to the backend only through the HTTP/JSON contract in [backend/README.md](../backend/README.md); it never holds GitHub credentials.

## Run on the phone

Start PostgreSQL and the backend first (see the backend README). Install reader dependencies once with `npm ci --ignore-scripts` in `android/reader-web`. Then, from the repository root:

```sh
ANDROID_HOME="$HOME/Library/Android/sdk" ./gradlew :app:testDebugUnitTest :app:assembleDebug --no-daemon
~/Library/Android/sdk/platform-tools/adb -s <device-serial> reverse tcp:8081 tcp:8081
~/Library/Android/sdk/platform-tools/adb -s <device-serial> install -r android/build/outputs/apk/debug/app-debug.apk
~/Library/Android/sdk/platform-tools/adb -s <device-serial> shell am start -n com.reporead.android/.MainActivity
```

`adb reverse` makes the phone's `127.0.0.1:8081` reach the Mac's loopback backend, so the registered GitHub callback is unchanged. It is reset when the phone disconnects — including when airplane mode or Wi-Fi loss ends wireless debugging. Re-enable wireless debugging and repeat it before syncing. Cleartext HTTP is permitted only to `127.0.0.1` (`res/xml/network_security_config.xml`). The base URL is a `BuildConfig` constant in `build.gradle.kts`.

## Signing and the release APK

Every build — release, debug, and the device-test APK — is signed with one personal key, so each installs over the last and keeps the phone's data. The key is outside the repository; `~/.gradle/gradle.properties` names it (paths only):

```properties
reporead.signing.storeFile=/Users/<you>/.config/reporead/release.jks
reporead.signing.passwordFile=/Users/<you>/.config/reporead/release-keystore-password.txt
```

Both files are mode 0600. It was created with `keytool -genkeypair -keystore … -storetype PKCS12 -alias reporead -keyalg RSA -keysize 4096 -validity 10000 -storepass:file … -keypass:file …` (certificate SHA-256 `20:49:29:9F:…:53:29:3F`). **Back up both files:** without them the next build cannot update the installed app, and installing one signed differently requires uninstalling it, which deletes the phone's saved notes and unsynced changes. Packaging without the properties fails with an explicit message; nothing falls back to the debug key.

```sh
ANDROID_HOME="$HOME/Library/Android/sdk" ./gradlew :app:assembleRelease --no-daemon
~/Library/Android/sdk/platform-tools/adb -s <device-serial> install -r android/build/outputs/apk/release/app-release.apk
```

The release build is not debuggable (no WebView DevTools, no `run-as`) and not minified. It uses the same backend address as development, `http://127.0.0.1:8081` through `adb reverse`, so refreshing and syncing need the phone on wireless debugging with the Mac; saved notes, highlights, and progress work offline and sync later. Hosting the backend is a separate decision. To inspect the phone's database, install the debug build over it (same key and app id; data is kept), then the release build again.

## Device tests

These run the Room cache and pending-change rules against an in-memory database on the phone, plus isolated WebView study checks and real reader Activity-recreation tests. The lifecycle tests use a debug-only, non-exported Activity and explicitly test-only saved pages; they make no network calls and never access the app's database. The host is absent from release builds. Install and run them with adb, which keeps the installed app and its data:

```sh
ANDROID_HOME="$HOME/Library/Android/sdk" ./gradlew :app:assembleDebug :app:assembleDebugAndroidTest --no-daemon
~/Library/Android/sdk/platform-tools/adb -s <device-serial> install -r android/build/outputs/apk/debug/app-debug.apk
~/Library/Android/sdk/platform-tools/adb -s <device-serial> install -r -t android/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
~/Library/Android/sdk/platform-tools/adb -s <device-serial> shell am instrument -w com.reporead.android.test/androidx.test.runner.AndroidJUnitRunner
```

They need the debug build installed; reinstall the release build afterwards. `./gradlew :app:connectedDebugAndroidTest` runs the same tests but **uninstalls the app afterwards**, deleting its session, cache, and any unsynced changes; do not use it on the phone you read on.

## Behavior

- **Sign-in:** a Chrome Custom Tab opens `/app/sign-in` with a PKCE challenge; the `reporead://auth` redirect is exchanged with the verifier for a bearer session, encrypted with an Android Keystore AES-GCM key. A 401 (expired session, or the backend restarted and lost its GitHub token) signs the app out of the network only: saved notes stay readable and the library offers **Sign in with GitHub**. **Sign out** revokes the session and deletes this phone's cached notes, images, and unsynced changes.
- **Offline cache (Room):** repositories, document lists, and the latest complete rendered copy of each opened note, keyed by document and blob SHA. **Save all notes on this phone** (a repository's overflow menu) fetches, one note at a time, every note whose saved copy is missing, of another version, or of an older page format, using the saved note list (refresh the repository first to pick up GitHub changes). A note the server refuses to render (too large) is listed and skipped; any other failure, or leaving the screen, stops the run and keeps the copies already saved, so running again continues. Images are not fetched by it; they are saved when the note is read online. A note whose cached version and path match the document's current version and path opens without a network call. Otherwise the current version is fetched; if that fails, the older saved copy is shown with the reason. Failed refreshes never replace saved lists or notes. There is no eviction yet; every saved note's latest version is kept (on the Pixel, 653 notes take 28.8 MB).
- **Reading position:** the reader saves the first block visible at the top of the screen (heading path, 64-character text prefix, block index) and scroll percent 0.7 s after scrolling stops, when the app goes to the background, and when leaving the note. Once captured, the bounded local database write finishes even if rotation cancels the Activity's UI scope; it does not start a network sync. It records the blob SHA actually displayed; refreshing a repository never changes it. Restoring tries heading + text, text, section, block index, then percent, and says when it is approximate or when the note changed since the last read. The system font size is applied to the reader.
- **Continue reading and bookmarks:** the library shows the five most recently read notes and all bookmarks. Saves and bookmark toggles are stored locally as pending and sent when the library opens or **Sync** is tapped; pending changes win over older server state and yield to newer state. There is no background sync.
- **Highlights and notes:** select text within one block and choose **Highlight** or **Add note** from the selection menu. The selection is read through `evaluateJavascript` using the Stage 0 contract (block id, UTF-16 offsets into canonical text); the page still cannot call native code. A new highlight is saved locally as a pending creation with a client mutation id in one Room write, then sent immediately and again on each library open, **Sync**, or note open until the server acknowledges it — the same id every time, so a lost acknowledgement cannot duplicate it. A refusal (e.g. the text no longer matches) is kept and shown, not retried. **Notes** lists the note's highlights with Show, Edit note, and Delete, then **Linked from**: the notes whose saved copies link to this one, found on the phone (offline) by resolving every saved page's note links as a tap would; a link that could mean several notes counts. It says when only some of the repository's notes are saved, since the others' links are unknown. Editing and deleting acknowledged highlights are online only; a conflicting edit shows both texts and asks which to keep. Each highlight is drawn at the server's current location for it when that location is in the displayed version; a pending creation is drawn where it was made. A highlight the server re-anchored after an edit says what its text is now. An **orphaned** highlight (the note changed and the passage could not be found reliably) shows its original selection with its context and a **Reattach** button: select the passage in the note, then choose **Reattach here** from the selection menu (online; the server verifies the selection). Notes removed from the repository are labelled in Continue reading and Bookmarks; their history and highlights are kept.
- **Changes since last read:** the library marks Continue reading entries "Updated since you read", lists every read note whose current version (in the saved note lists) is not the one last read, and lists the five most recently changed other notes as "Not read yet" or "Read", each with when a refresh saw it change. Opening a note whose last-read version differs from the displayed one shows **Changed since you last read**: changed, new, and removed sections with line counts; tapping a current section scrolls to its heading. The last-read version is captured before the reader saves the displayed one, so the summary appears once per opening; after reading, the new version is the baseline. Online only and not cached; a failure is shown with **Try again**. A note never read shows nothing.
- **Search:** searches only what is on the phone: every listed note's title and path, the text of saved notes, and highlights with their notes. With nothing typed it says how many notes are searched by their text, for example "Searching 653 of 654 notes by their text".
- **Links between notes:** tapping an Obsidian `[[link]]` or a relative `.md` link resolves it like Obsidian against the repository's saved note list (works offline): an exact path, a name with a folder, or a file name, preferring the linking note's folder. One match opens a **preview** sheet: title, folder, and the saved copy from its start or from the linked heading, in a separate isolated page where nothing navigates; **Open** opens the note. Without a saved copy the sheet says so (Open fetches it). When several notes share the name the app asks which one and opens it. A `#Heading` opens the note at that heading instead of the saved position; it may be the heading's text (Obsidian) or its GitHub anchor (`#2-separate-the-contracts-and-checks`, repeats numbered `-1`, `-2`). An unknown name says so. `![[image.png]]` embeds show the image (resolved by the server by name; refresh the repository once so it knows the image files).
- **Outline and current section:** the top bar's subtitle is the heading of the section at the top of the screen, updated 150 ms after scrolling settles. **Outline** lists the note's headings by level with the current one marked; tapping one scrolls to it. Headings are read from the page through `evaluateJavascript`, like the reading position.
- **Study view (P3):** **Study** appears only when a note has a recognized heading. `Problem` stays visible; `Approach`, `Brute Force Approach`, `Optimized Approach`, `Complexities`, and `Mistakes` collapse until tapped. Items under `Questions this file answers` appear one at a time. `Review and practice` uses each list item with its leading instruction; prose-only sections use only their first paragraph. These prompts appear one at a time, with **Read the answer** showing the note at that question (there is no inferred question-to-answer mapping). **Read** leaves study view. Blocks keep their canonical text; a collapsed section's heading stands in for hidden content when saving/restoring, and jumping to a highlight reveals its section. Question recall saves the current question's anchor and measures progress against the note, not the short panel. Study mode survives activity recreation but is not a stored preference.
- **Practice (Library):** an offline list of question items extracted from saved pages, shuffled one item per note per round, starting with a topic picker built from the real folder hierarchy (e.g. `core/databases`, including subfolders). **All topics** explicitly chooses a mixed queue; **Topics** returns to the picker. It reports question counts and saved/listed coverage within the topic, including notes not yet saved; it never fetches notes to fill the list. Tap a question to open its note in study view at that item; Back preserves the Practice tab, topic, shuffle order, and list position while the saved pages are unchanged. Each target uses the saved page's blob SHA and block id, so identical prompts remain distinct. If the displayed version differs or the block is missing, the reader explicitly shows the note and asks you to choose again from Practice; it never guesses from question text. Recognition and extraction belong to `reader/Study.kt`; Android uses jsoup (the backend's existing pinned version) to parse saved HTML, including loose lists and entity-escaped canonical text. No scores, scheduling, AI, source edits, or new schema/API; building/shuffling the list and toggling study make **0 external calls**. Opening a note keeps the existing reader's fetch/sync behavior.
- **Review cards (P4):** in a note, select an answer and choose **Make a question**, or use **Make a question** on a highlight in Notes. Write a question; the selected canonical passage is its answer. **Add to review** on a Practice item, or **Add question to review** in Study, keeps the authored prompt and asks you to select its answer; no answer mapping is inferred. Question/answer authoring survives recreation. Creation uses the existing pending annotation mutation and idempotent push. **Review cards** in Library starts a shuffled, note-interleaved due session capped by the server's notebook response (40); without that response it asks for Library sync first. Reveal shows the exact answer and its canonical block context, then Again (0), Hard (3), Good (4), Easy (5). Each grade is one local pending UUID, written completely even if recreation cancels the UI. The log owns session completion across recreation; grades are pushed on Library open/Sync, after card creations, and immutable duplicate requests are safe. A refused grade is visible and excluded from scheduling, not retried.
- **Changed cards:** every known note-version change blocks review until the answer is resolved, saved locally, and explicitly confirmed using **Answer is correct** in Notes (online). This conservative rule also covers edits elsewhere in the answer's section without relying on an unavailable diff. Orphans use the existing selection-based **Reattach** path, then need confirmation. Conflicting server metadata and a stale local note list also block review. Offline, only the last known repository version is available; unseen GitHub edits cannot be detected until refresh. The sole pure SM-2 scheduler is `library/Review.kt`: initial ease 2.5, intervals 1/6/ceil(previous × prior ease), ease floor 1.3, failure resets repetitions. Each card appears once per bounded session; failures are due next day, not repeated indefinitely in the same session.
- **Notebook:** Library's **Notebook** shows every cached highlight/card, including removed notes and pending creations, with folder (including descendants), note and orphan filters. Library sync fetches the complete server notebook without GitHub calls. **Open passage** opens the reader at the saved annotation and shows Notes; missing/orphaned passages remain available there for reattachment. **Export Markdown** shares the filtered entries as a UTF-8 `.md` attachment via a non-exported FileProvider limited to `files/exports/`. Quotes preserve their exact characters, blank lines, CRLF, Unicode and trailing whitespace. Export writes an immutable file atomically before sharing; failures are shown. Private export files are removed on sign-out, disconnect or account deletion along with cards and logs; copies already shared to other apps are outside RepoRead's control. Nothing is written to GitHub.
- **Footnotes:** a footnote reference shows its number (in definition order); tapping it shows the definition in a sheet at the bottom of the page without scrolling; tapping elsewhere closes it. Definitions stay where the note has them, each on its own line. The sheet is outside the note's blocks, so it cannot be highlighted or saved as the reading position.
- **Bars hide while reading:** a swipe that scrolls the note down at least 24 dp hides the top bar and the system bars when the finger lifts; one that scrolls up 24 dp, or ends near the top (also by a fling), shows them; a swipe from the screen edge shows the system bars briefly. They change only when the finger lifts: moving the WebView under a finger still on it made the page read the move as scrolling the other way, and the bars and page oscillated. Only scrolling that follows a touch on the page counts, so restoring the position, jumping from the outline, or **Show** never hides them. Driven by the WebView's own scroll and touch callbacks (the WebView does not take part in Compose nested scrolling). Leaving the reader shows the system bars.
- **Code blocks:** a row above each code block shows its language, **Copy**, and — while the code is wider than the screen — **Wrap** (layout only; not remembered). Copy is a same-origin `/copy-code?block=…` link the app intercepts; it reads the block's canonical text through `evaluateJavascript` and copies it without the final line break, so a pasted command does not run. The row is outside the block, so canonical text is unchanged.
- **Full-screen tables and diagrams:** a table wider than the screen and every rendered diagram has **Full screen** above it (a same-origin `/full-screen?figure=…` link the app intercepts). The figure opens alone with pinch zoom, system bars hidden, and rotation following the phone even when auto-rotate is off; leaving it restores the app's orientation. It is a separate isolated page built from the saved copy of the version the reader showed (same resources, no bridge, no navigation), so it survives the recreation that rotating causes. Highlights are not drawn or made there.
- **Images:** repository images referenced by a note are fetched through the backend by native code (the page never sees the token) and cached with that note version. Offline and uncached, an image shows `[Image unavailable: …]`; remote images are blocked.
- **Reader isolation:** backend-sanitized HTML in a WebView with app-bundled reader/Mermaid/highlight assets only, no credentials, no JavaScript bridge, and no network/file/content access. Tapped `http(s)` links open the browser; links between notes are not followed.

`reader-web/` holds the reader's display JavaScript and styles; see its README. `schemas/` holds exported Room schemas; version 2 adds `annotations` through a Room auto-migration, verified on the Pixel against an existing version 1 database; version 3 adds highlight locations, status, and original context, and the `deleted` flag on reading states and bookmarks (auto-migration with defaults); version 4 adds a note's refresh-found change time (`changedAt`, nullable), verified on the Pixel against its existing version 3 database; version 5 adds saved notes' search text; version 6 adds their page format (`renderFormat`), so a saved copy from an older format is fetched once more when opened online; version 7 adds card metadata, pending/durable review log projections and the server-owned session limit (auto-migration). The instrumented v6→v7 regression constructs the previously exported schema in a test-only database and verifies saved notes and unsent highlights survive.
